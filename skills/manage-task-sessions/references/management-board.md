# 要件ごとの管理ボード

管理ボードは親要件ごとに用意する。「状況を更新」は管理セッションで GitHub と子の状態を読み直す操作。「同じ子に追加指示」は対象の task / PR と利用者の指示文を管理セッションに渡す操作。元の管理会話に依頼が届いたことと、担当の子から返信が届いたことは別々に確認する。

## Claude Code の管理セッション

管理ボードは `task-board` mod（`software-factory` の依存の plugin）で表示する。mod は管理セッションの中で動き、管理セッションが渡した記録を一覧する。依頼の宛先は常に管理セッションで、mod から子へ直接は送らない。

1. ツール一覧に `mcp__task-board__update_board` があれば `task-board` が読み込まれている。ない場合は mod を使わず、同じ内容の一覧をこの会話に表示し、利用者からの指示も会話で受ける。
2. ボードの作成時と、子の作成・PR の紐付け・状態の確認などで担当の記録が変わるたびに `mcp__task-board__update_board` を呼ぶ。呼ぶたびに記録全体が置き換わるので、変わった task だけでなく親要件のすべての task を毎回渡す。
   - `requirement`: 親要件の `repository`（`owner/repo`）、`number`、`title`、`url`、`state`
   - `tasks`: task ごとの `number`、`title`、`url`、`state`。PR があれば `pr`（`number`、`url`、`state`）、担当の子がいれば `child`（`runner` は `claude` か `codex`、`id`、任意で `url`）
   - `checkedAt`: 管理セッションが状態を確認した時刻（ISO 8601）

   `state` には Issue の状態と workflow ラベルを渡す（例: `open / workflow:in-progress`、`closed`）。`closed` などを含む task が完了に数えられる。`child.id` は Claude Code の子なら `session_` から始まる session ID、Codex の子なら task ID を渡す。入力の形が違うと拒否されるので、示された理由に従って直して呼び直す。
3. 初回の呼び出しでパネルが開く。後から開くとき、または利用者が状況を見たいときは、利用者が `/task-board` を実行する。
   - **デスクトップアプリ・ターミナル**: チャット横のパネルで確認する。各 task の行から「状況を報告してもらう」ボタンや入力欄で、管理会話に追加指示の依頼を送れる。
   - **モバイルアプリ**: mod の描画先にならないため、`/task-board` の返答の文字一覧で確認する。モバイルからの指示は会話に直接書く。
4. `[管理ボード]` から始まる依頼を受けたら、依頼文の task 番号と子の ID を担当の記録と GitHub で照合する。一致すれば同じ子に指示を転送し、子の返信を確認して利用者に報告する。担当の記録と食い違う場合は転送せず、その旨を報告する。照合や転送で担当の記録が変わったら、`mcp__task-board__update_board` で全体を渡し直す。
5. mod は実行先が `claude` の子の状態と最新の返信を定期的に自動取得して表示する。パネルの「状況を更新」ボタンは冒頭の「状況を更新」とは異なり、この自動取得を取り直すだけで、管理セッションは GitHub を読み直さない。`codex` の子は自動取得せず、管理セッションの記録を示す。セッションに `claude-code-remote` がない場合（クラウドセッションを手元のターミナルで開いた場合や、手元の管理セッション）は、mod は自動取得を止めて管理セッションの記録だけを表示する。指示の送信はその場合も使える。
6. 自動取得の表示は参考情報とする。子への到達や子からの返信は、管理セッションが子の状態と履歴で確認する。GitHub と担当の状態を読み直したいときは、管理会話で依頼する。

他の人にボードを共有したい場合は、読み取り専用のスナップショットを Artifact として公開できる。

## Codex デスクトップの管理チャット

Codex は利用環境と利用者の希望に合わせて管理ボードの実現方法を選ぶ。後からボードを開いて進捗を確認し、対象の task / PR を選んで、同じ管理チャット経由で担当の子に追加指示を出せるようにする。作成後は、再び開く方法と指示の出し方を利用者に伝える。
