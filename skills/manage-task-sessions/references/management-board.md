# 要件ごとの管理ボード

管理ボードは親要件ごとに用意する。「状況を更新」は管理セッションで GitHub と子の状態を読み直す操作。「同じ子に追加指示」は対象の task / PR と利用者の指示文を管理セッションに渡す操作。元の管理会話に依頼が届いたことと、担当の子から返信が届いたことは別々に確認する。

## Claude Code の管理セッション

1. 親要件を管理している会話で「この要件の管理ボードを非公開の Artifact にして」と依頼する。タイトルにリポジトリ名と要件番号を入れ、返された URL をこの会話に記録する。
2. 後からは元の管理セッションを再開し、記録した URL または `/artifacts` からボードを開く。
3. 管理セッションが Artifact のコメントを受け取れる環境では、対象の行に「状況を更新」または「PR 番号・同じ子への追加指示」を書き、**Send to Claude** で送る。コメント送信が使えない環境では、対象と指示文をコピーできるようにして、元の管理会話に貼り付ける。受付が不明な場合は貼り付ける前に会話の履歴を確認する。
4. 管理セッションで依頼を処理し、確認した状態や子の返信を同じ Artifact に反映する。再公開すると同じ URL で更新を確認できる。[Claude Code の Artifacts 公式手順](https://code.claude.com/docs/en/artifacts)

## Codex デスクトップの管理チャット

チャットで task / PR を指定して直接依頼することもできる。会話内に一覧と操作ボタンを置きたい場合は、次の手順を使う。

1. 親要件の管理チャットで、会話内の可視化機能（利用可能なら `visualize`）を使い、操作できるボードを返信に埋め込む。利用者が再訪しやすいよう、この管理チャットをピン留めできることを案内する。この方式はローカルサーバーの起動を必要としない。
2. ボタンには現在のチャットへ依頼を送る機能を使う。たとえば `window.openai.sendFollowUpMessage({ prompt, title })` の `prompt` に、更新ならリポジトリと親要件、追加指示なら対象の task / PR と入力された指示文も含める。例は「PR #123 を担当する同じ子に、次の修正を依頼して」。確認画面が表示されたら利用者が内容を確認して送る。
3. 後からは同じ管理チャットを開き直し、過去の返信にあるボードで操作する。「状況を更新」の依頼がこのチャットの新しいメッセージとして届くことを確認する。追加指示の場合は管理中の同じ子に送り、その返信を確認する。
4. 確認時点を更新したボードをこのチャットの返信に再掲する。埋め込みや送信機能が使えない場合は、対象と指示文を同じチャットに入力できる形で示す。
