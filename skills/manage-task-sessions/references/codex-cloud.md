# Codex Cloud の操作例

## 管理ツールと CLI

- **作成**。その場の `create_thread` が `codexCloud` を受け付ける場合は、`list_cloud_environments` から対象 repository の実行可能な `environmentConfigId` を選ぶ。CLI が対象環境を認識する場合は `codex cloud exec --env "$env_id" --branch "$branch" "$prompt"` でも新規作成できる。環境 ID は各手段が返した値を使う。作成結果の正式なチャット ID または URL、環境名、返された `hostId` を記録する。

## 同じ子への追加指示

1. 記録したチャット ID と `hostId` で同じ子を指定し、`send_message_to_thread` で追加指示を一度送る。Web で作成した子も同様に扱える。`codex cloud exec` は新規作成用。
2. `wait_threads` で送信後のターンを確認する。受領通知や前回と同じ回答しか得られない場合、または送信結果が不明な場合は、`read_thread` でツール出力も含めて履歴を読み、今回の指示本文が届いたかを確かめる。子が作業中ならそのまま待つ。PR の修正を依頼した場合は、同じ PR の差分に依頼内容が反映されたかを確認する。
3. 未達が確認できたときだけ同じ子に再送する。本文が届いていても、子が依頼を取り違えたままターンを終えた場合は、対象と残作業を明示して同じ子に指示し直す。管理ツールで続行できない場合は下記の Web 画面を使う。到達を判断できない間は再送を保留する。

## Web 画面

[ChatGPT](https://chatgpt.com/) で新しいチャットの「実行場所」→「クラウド」から公開済み環境を選ぶ。表示された環境名を確認して初回の依頼を送る。作成中の一時 URL が正式なチャット URL に切り替わったら記録する。

追加指示に Web が必要な場合は、記録済みの子の URL を開く。直前の送信結果が不明なら、まずその会話の履歴を確認する。追加指示は「フォローアップの変更を求める」欄から送る。ログインや利用者による承認が必要なら、その操作を利用者に渡す。
