# 要件の作業セッションを管理する

この会話を親要件の窓口にする。利用者は task や PR を指定して仕事を頼み、同じ会話からその担当に追加指示を出せる。

## 担当と委任範囲

この会話で作成した子について、親 Issue URL、task / PR URL、実行先、子を再び指定できる ID または URL を記録する。GitHub の native parent と PR が閉じる task を照合し、管理中の task に PR ができたら同じ担当に紐付ける。task と PR のどちらで依頼されても既存の担当を使う。対応が曖昧なら起動記録と GitHub を確認し、それでも特定できない場合だけ利用者に尋ねる。

担当がいなければ、指定された実行先（省略時は Claude）に子を作る。親と対象の URL、作業元の branch、使うスキル、依頼範囲と完了条件を渡す。子の環境には対象 repository へのアクセスと担当スキルが必要。

- 新規実装は `implement-task` に委ね、着手条件と repository 単位の排他を子の実行中も守る。
- 既に open PR があれば `pr-resume` に委ね、実際の head repository / branch の最新の push 済み commit から同じ PR を更新する。定期実行が作った PR も引き継げる。元のセッションは管理対象に加えず、作業が競合する間は起動を待つ。

## 手段の選び方

作成・追加指示・返信確認の各操作で、意図した環境や子を指定でき、利用者の操作が少なく済む手段を選ぶ。管理セッションから直接操作できる手段を優先し、必要な部分だけ Web で補う。手段を切り替えても宛先は維持する。起動や送信の成否が不明なら、記録と子の履歴を照合して重複を防ぐ。担当がアーカイブ済みなどで続行できないときは理由を返し、新しい子への引き継ぎを依頼された時点で対応を更新する。

操作方法や制約を確認したいときは、実行先に応じて [Claude Code の CLI 操作例](references/claude-code.md) または [Codex Cloud の管理ツール・CLI・Web 操作例](references/codex-cloud.md) を参照する。

## 完了条件

対象と子へのリンクまたは ID を添え、依頼された範囲で確認できた結果を返す。

- **起動・送信**では、意図した宛先での受付を確認する。子の履歴にも指示が記録されていれば、到達まで確認できたと伝える。
- **返信の確認**では、同じ子の今回の返答が追加指示に答えているかを確認する。前回と同じ回答や受領通知だけなら、その内容と未確認の点を報告する。
- **作業完了の確認**では、対象 PR の変更や検証結果など、依頼の完了条件を満たす成果物を確かめる。
