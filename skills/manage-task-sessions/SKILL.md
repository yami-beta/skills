# 要件の作業セッションを管理する

この会話を親要件の窓口にする。利用者は task や PR を指定して仕事を頼み、同じ会話からその担当に追加指示を出せる。

## 状況把握と指示出し

起動時に、この会話または指定された Issue・PR から対象の親要件を特定する。特定できない場合だけ利用者に親 Issue を尋ねる。この会話の記録から同じリポジトリ・親要件の管理ボードを確認し、初回は作成して開き方を記録する。再実行時は既存のボードを更新する。

GitHub と担当の子の履歴を確認し、対応待ちの task から順に、担当の子、PR、確認時点の状態、次に取れる操作をボードに示す。スキルの起動だけならボードの開き方を返して完了する。委任や追加指示も依頼された場合はその作業まで進め、確認できた結果をボードに反映する。

会話内で操作できる表示が使える場合は、対象を選んで「状況を更新」「同じ子に追加指示」を管理セッションへ依頼できるようにする。送る前に宛先と指示文が読めるようにし、管理セッションが最新の状態と担当を照合して実行する。表示機能がない環境でも、一覧にある task / PR 番号と指示をこの会話に入力すれば同じ操作に進める。

ボードの作成・再訪には、管理セッションを開いているアプリに応じて [Claude Code と Codex の管理ボード手順](references/management-board.md) を使う。ボードからの依頼は、ボードの記録や通知、コメント、貼り付けを通じてこの会話で受け取る。担当を照合して子に転送し、処理状態と更新した一覧、子からの返信を利用者に返す。

## 担当と委任範囲

この会話で作成した子について、親 Issue URL、task / PR URL、実行先、子を再び指定できる ID または URL を記録する。GitHub の native parent と PR が閉じる task を照合し、管理中の task に PR ができたら同じ担当に紐付ける。task と PR のどちらで依頼されても既存の担当を使う。対応が曖昧なら起動記録と GitHub を確認し、それでも特定できない場合だけ利用者に尋ねる。

担当がいなければ、指定された実行先（省略時は Claude）に子を作る。親と対象の URL、作業元の branch、使うスキル、依頼範囲と完了条件を渡す。子の環境には対象 repository へのアクセスと担当スキルが必要。

- 新規実装は `implement-task` に委ね、着手条件と repository 単位の排他を子の実行中も守る。
- 既に open PR があれば `pr-resume` に委ね、実際の head repository / branch の最新の push 済み commit から同じ PR を更新する。定期実行が作った PR も引き継げる。元のセッションは管理対象に加えず、作業が競合する間は起動を待つ。

## 手段の選び方

作成・追加指示・返信確認は管理セッションから始める。起動や送信の成否が不明なら、起動記録と子の状態・履歴を照合して重複を防ぐ。子が作業中なら同じ子の返信を待つ。

利用者による操作を求められたとき、または管理セッションで利用できる手段では対象の操作を実行できないと確認したときに限り、宛先を維持してその操作だけ別の手段に切り替える。以後の進捗・返信・PR の確認は管理セッションに戻す。担当がアーカイブ済みなどで続行できないときは理由を返し、新しい子への引き継ぎを依頼された時点で対応を更新する。

操作方法や制約を確認したいときは、実行先に応じて [Claude Code の操作例](references/claude-code.md) または [Codex Cloud の操作例](references/codex-cloud.md) を参照する。

## 完了条件

対象と子へのリンクまたは ID を添え、依頼された範囲で確認できた結果を返す。

- **起動・送信**では、意図した宛先での受付を確認する。子の履歴にも指示が記録されていれば、到達まで確認できたと伝える。
- **返信の確認**では、同じ子の今回の返答が追加指示に答えているかを確認する。前回と同じ回答や受領通知だけなら、その内容と未確認の点を報告する。
- **作業完了の確認**では、対象 PR の変更や検証結果など、依頼の完了条件を満たす成果物を確かめる。
