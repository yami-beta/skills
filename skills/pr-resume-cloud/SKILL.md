# Pull Request の作業をクラウドセッションへ委譲する

クラウドセッションを起動し、PR の head branch で今後の作業を任せる。この skill の役割は委譲であり、PR の残作業の把握・実装・検証はクラウド側が行う。

## 対象と依頼範囲

指定された PR、または現在の branch に対応する open PR を対象とする。一意に特定できなければ利用者に尋ねる。

残作業の有無や内容をローカルで判定しない。PR の内容を理由に委譲の可否を確認せず、残作業がなさそうに見えても委譲する。補足指示があればその範囲をクラウド側へ渡し、なければ「PR を引き継いで、元の要件の未達、確認できる不具合、有効なレビュー指摘、変更に起因する CI 失敗に対応し、PR を更新する」を依頼範囲とする。

## 起動前の確認

委譲自体ができるかだけを確認する。

- PR が open であること。closed / merged の PR は委譲せず、代わりの PR も作らない。
- head branch が remote 上にあり、クラウドから取得できること。fork の PR では head repository へ push できる見込みがあること。
- PR の head branch に対するローカルの未 push の変更を取りこぼさないこと。push が依頼範囲に含まれなければ起動前に確認する。

これらに問題がなければ確認せずに起動する。

## クラウドセッションの起動

現在のセッションから、実行環境に組み込みのクラウド起動機能を使ってクラウドセッションを起動する。利用可能な機能と指定方法は実行時に確認し、ローカルの遠隔操作をクラウド実行と混同しない。CLI を別プロセスとして起動したり、疑似端末を用意したりする回避策はとらない。組み込みの機能で起動できなければ、そのまま使える引き継ぎ文と必要な手動操作を返す。

開始 branch を指定できる機能では、PR の head branch を指定する。指定できない機能や、環境が既定の作業 branch を用意する機能でも、引き継ぎ文で最初に head branch へ切り替えさせることで、作業 branch を PR の head branch にする。

クラウドの環境は、利用者の指定か実行環境の既定に従い、推測で選ばない。指定が必須で一つに定まらない場合は確認する。

起動結果が不明なら実状態を確認してから再試行し、重複したセッションを作らない。起動後は同じ作業をローカルで進めない。セッションタイトルを設定できる場合は `#123 <PR タイトル>` のように PR 番号が分かる名前にする。

## 引き継ぎ文

クラウド側に skill や元の会話があることを前提にせず、skill の呼び出しも指示しない。次を含む自己完結した引き継ぎ文を渡す。

- 作業を始める前に、PR の head repository / branch を checkout し、現在の branch がそれであることを確認すること。環境が既定の作業 branch や push 先を指示していても、PR の head branch を優先すること。
- PR URL と依頼範囲、終了条件。
- PR 本文、関連する要件、差分、レビュー、最新 head の CI から残作業を把握し、現在のコードと検証結果に照らして判断すること。
- 追加コミットは PR の head branch へ push し、別 branch や新しい PR で代替しないこと。push できない場合は、変更の所在と PR への反映に必要な操作を報告すること。
- 既存の成果・履歴・attribution を保持し、force push や履歴の書き換えを既定の手段にしないこと。範囲外の改善を混ぜないこと。
- 変更に応じた検証を行い、PR URL、変更の要点、検証結果、push 先の branch、残った懸念を報告すること。

## 完了条件

意図したクラウドセッションが作業を受け付けたことを確認する。委譲先の URL / ID、開始 branch、使われた環境、残っている手動操作を返す。開始 branch が PR の head branch でない場合は、引き継ぎ文で切り替えを指示したことと、セッションの表示上の branch がずれることを伝える。起動しただけの状態を PR 更新済みと扱わず、委譲先の完了の監視は依頼された場合に行う。
