# Pull Request の作業をクラウドセッションへ委譲する

対象 PR の head branch から開始するクラウドセッションを起動し、PR の今後の作業を任せる。この skill の役割は委譲であり、PR の残作業の把握・実装・検証はクラウド側が行う。

## 対象と依頼範囲

指定された PR、または現在の branch に対応する open PR を対象とする。一意に特定できなければ利用者に尋ねる。

残作業の有無や内容をローカルで判定しない。PR の内容を理由に委譲の可否を確認せず、残作業がなさそうに見えても委譲する。補足指示があればその範囲をクラウド側へ渡し、なければ「PR を引き継いで、元の要件の未達、確認できる不具合、有効なレビュー指摘、変更に起因する CI 失敗に対応し、PR を更新する」を依頼範囲とする。

## 起動前の確認

委譲自体ができるかだけを確認する。

- PR が open であること。closed / merged の PR は委譲せず、代わりの PR も作らない。
- head branch が remote 上にあり、クラウドから取得できること。fork の PR では head repository へ push できる見込みがあること。
- PR の head branch に対するローカルの未 push の変更を取りこぼさないこと。push が依頼範囲に含まれなければ起動前に確認する。

これらに問題がなければ確認せずに起動する。

## クラウドセッションの起動

実行環境に組み込みのクラウド起動機能を使い、開始 branch を PR の head branch に指定する。利用可能な機能と指定方法は実行時にヘルプや公式資料で確認し、ローカルの遠隔操作をクラウド実行と混同しない。

- Claude Code CLI の `claude --cloud "<引き継ぎ文>"` は現在の branch の remote 上の状態から開始するため、先に head branch を checkout して remote と一致させる。利用者の checkout と未コミット変更を変えないよう、一時的な worktree から起動するか、起動後に元の branch へ戻す。
- Codex CLI の `codex cloud exec --env <ENV_ID> --branch <head branch> "<引き継ぎ文>"` は開始 branch を直接指定できる。
- 開始 branch を指定できない機能では、開始後に head branch を checkout させる指示で補う。

クラウドの環境は skill 側で選ばない。Claude Code CLI は、作業対象 repository の project settings などに設定された `remote.defaultEnvironmentId` を既定の環境として使うため、その設定に従う。環境の指定が必須の機能では、利用者が指定した環境、または対象 repository に対応する環境が一つに定まる場合はそれを使い、定まらなければ確認する。

起動結果が不明なら実状態を確認してから再試行し、重複したセッションを作らない。起動後は同じ作業をローカルで進めない。セッションタイトルを設定できる場合は `#123 <PR タイトル>` のように PR 番号が分かる名前にする。

## 引き継ぎ文

クラウド側にこの skill、`pr-resume`、元の会話があると仮定せず、次を含む自己完結した引き継ぎ文を渡す。クラウド側で `pr-resume` を使える場合は、それに従って作業するよう添える。

- PR URL と、push 先の head repository / branch。環境既定の作業 branch ではなく、ここへ追加コミットを push すること。別 branch や新しい PR で代替しないこと。
- 依頼範囲と終了条件。
- PR 本文、関連する要件、差分、レビュー、最新 head の CI から残作業を把握し、現在のコードと検証結果に照らして判断すること。
- 既存の成果・履歴・attribution を保持し、force push や履歴の書き換えを既定の手段にしないこと。範囲外の改善を混ぜないこと。
- 変更に応じた検証を行い、PR URL、変更の要点、検証結果、push の状況、残った懸念を報告すること。

## 完了条件

意図したクラウドセッションが作業を受け付けたことを確認し、確認できる範囲で開始 branch が PR の head branch であることも確かめる。委譲先の URL / ID、開始 branch、使われた環境、残っている手動操作を返す。起動しただけの状態を PR 更新済みと扱わず、委譲先の完了の監視は依頼された場合に行う。
