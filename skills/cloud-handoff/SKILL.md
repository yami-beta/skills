# ローカルの作業をクラウドへ引き継ぐ

現在の作業を、正しいコードと文脈からクラウドで継続できる状態にする。移行先と作業範囲は利用者の指定を優先し、「準備だけ」と「実行開始まで」を区別する。

## 引き継ぎ方針

実行環境に組み込みのクラウド引き継ぎ機能があれば優先する。その機能がコードや会話を転送する場合は、別の引き継ぎ資料や転送処理を重ねず、不足する情報だけ補う。利用可能な機能と転送範囲は実行時に確認し、ローカルの遠隔操作や接続済みホストへの移動を、クラウド移行と混同しない。

直接引き継げない場合は、クラウド側が取得できるコードと、目的・決定事項・実装済みの内容・残作業・検証結果をまとめた短い引き継ぎ文を渡す。元の会話やローカルのファイルが自動で届くとは仮定しない。自動で開始できなければ、利用者がそのまま使える引き継ぎ文と必要な手動操作を返す。

## 守ること

- 未コミット・未追跡・未 push の必要な変更を取りこぼさず、無関係な変更や秘密情報を含めない。ローカルの変更と既存履歴は保持する。
- 引き継ぎ実行の依頼には、必要な対象変更の commit・既存の作業用 remote への push・クラウドセッションの起動を含める。利用者が制限した操作は行わず、移行先や転送範囲を判断できない場合だけ確認する。
- クラウド側に渡す依頼範囲と終了条件を保持する。移送機能で届かない依存物や環境設定、未解決の判断は不足として伝える。
- 引き継ぎ後に同じ作業をローカルで重複して進めない。結果が不明なら実状態を確認してから再試行し、元のセッションや worktree を自動で削除・アーカイブしない。

## 完了条件

意図したクラウドセッションが作業を受け付けたことと、確認できたコード・文脈の転送状況を報告する。引き継ぎ先の URL / ID、現在の状態、残っている手動操作や不足があれば簡潔に伝える。準備のみ・起動待ち・失敗を実行開始と扱わず、作業完了の継続監視は依頼された場合に行う。
